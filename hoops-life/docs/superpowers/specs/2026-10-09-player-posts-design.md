# Player posts, replies and remembered public choices

The user wants detailed realistic player posting alongside interviews, with reactive people and media as a core part of both modes. Continue the authored in-save world rather than representing outside footage as simulated events.

Build saved public posts with original speaker/team/date/context, photo pieces, varied fan/teammate voices, and a single reply from the user. Career can speak only as its own player; Franchise can select current roster players. Organized topics: team-first, back-to-work, next-opponent challenge, and celebrating an actual win. Posting is limited to once per speaker per seven calendar days; replies once per post, with one reply per user per day. Public choices affect remembered trust/fan confidence and bounded Career reputation, not arbitrary ratings.

An opponent challenge records the next real scheduled fixture. Its assessment uses the exact game and actual appearance/points/minutes/team result. No other game resolves it. Team departure, retirement or missing/cancelled fixture cancels it; DNPs never become personal triumphs. Celebrations reference a recent saved actual team win, with DNP wording distinct from an appearance. No old team win or fabricated performance qualifies.

League stars can also post after a qualifying actual performance (30 points or a triple-double), bounded in frequency and deterministic without consuming simulation RNG. The entry retains the actual box facts and original club. This gives the user other people to react to. Reply choices support, congratulate or challenge; congratulating a loss or DNP is not accepted. Replies produce differing authored reactions and persistent person memories, with a same-day limit preventing reputation farming.

Modern presentation uses photographic post cards. Older eras use public player statements in print/radio/letters and appropriate language, without social counters. Use original real player photos and current-team garments as labeled composites; the created player remains faceless. Preserve source context when a player later changes clubs. Saved data is bounded; JSON/IndexedDB and Live Game mutation guards apply.
